# Incidents behind the static-first rules

Dated stories with the rule each supports. The rules are in SKILL.md.

- **2026-09-03, Zero to Signing, vendoring load-bearing.** The registry `@stacks/connect` and `@stacks/transactions` could not serialize the pox-5 `staking-postcondition` type; the vendored bundles in `src/vendor/` were the only copies that could send it. Rule: vendoring can be load-bearing for correctness.
- **2026-09-03, Zero to Signing, screenshots rotted.** Eight one-off PNG files in the project root did not update when the cycle bar changed; two committed shot scripts replaced them. Rule: screenshots from a committed script.
- **2026-09-03, Zero to Signing, 116 green checks and a wrong bar.** Every cycle-bar defect was found by a person reading images. Rule: functional assertions do not see design.
- **2026-08 to 2026-09, Zero to Claiming, live network finds.** Rate-limit unit (per minute, not per second), a source-fetch race, a chunk-cost ceiling, a cached transient failure, a roster union: each found live, each became a fixture-driven check the same day. Rules: smoke-test live; the harness is the center of gravity.
- **2026-08-16, sBTC Deposit Recovery, ported reference caught the PRD.** `verify-fixtures.py` (15 checks) ported to `verify-crypto.mjs` before any UI caught the PRD's signer-key byte slice ([-68:-2] against the true [-66:-2]) on first run. Rule: parity-test against an independent implementation.
- **2026-08, sBTC Deposit Recovery, healed backend.** Both real deposits were registered after the fix, so the broken branch became untestable live; fixtures record the pre-fix state. Rule: golden fixtures record the pre-fix state.
- **2026-09-30, sBTC gas swap, fixture 404s.** With an injected `fetch`, the `tx-replaced` fixture answers 404 forever while the console stays clean, because the response is an object and not a network event. Rule: two interception styles, two error rules.
- **2026-09-12, sBTC gas swap, absolute data path.** The first upload baked in an absolute `sponsors.json` path and broke relay discovery. Candidate: resolve co-deployed data relative to the page.
- **2026-10-03, zero_to homepage, Jekyll.** Skill texts with YAML front matter were converted by Jekyll and the live skills page showed empty boxes; the local server served the files verbatim and could not see it. `.nojekyll` and a harness check fixed it. Fact in constants.
- **2026-10-02, zero_to homepage, timer test one short.** The fetch a fake-clock timer triggers is still asynchronous; the count read one short until 300 ms of real time followed each `runFor`. Reference pattern in scaffold.
- **2026-10-15, tax export, cascade.** With balance changes missing, every transaction looked unreconciled and the next stage queued about 380 extra live requests. Candidate: a later stage acts only on items whose prerequisites loaded.
- **2026-10-15, tax export, chunk gone after deploy.** An open page could not load the Excel chunk after a deploy renamed it and showed "The Excel file could not be made"; a catch around the dynamic import now asks for a reload. Candidate: lazy import catch.
- **2026-10-19, tax export, replay rots by date.** The Frankfurter range is built from today's date, so the fixture recorded on 2026-10-15 stops answering on 2026-10-16 and 3 of 119 tests fail; the harness passed because its EUR scenario does not assert completeness. Rule: inject the clock; assert completeness in every scenario.
- **2026-10-18, sBTC Deposit Recovery, checks that cannot fail.** Two harness checks ended in `|| true`. Candidate: audit check bodies.
- **2026-10-18, three READMEs with stale counts.** sBTC Deposit Recovery ("eight outcomes", "100-check harness" against nine branches and 194 checks), tax export ("six stages", "30 columns", "94 checks" against seven, 32 and 99), zero_to homepage ("84 checks" against 88). Rule: never write counts in prose.
- **2026-09 to 2026-10, Zero to Claiming, verify without build.** `npm run verify` without a preceding build passed against the previous bundle. Rule: build before you verify. A live-site report of "v33 behaviour missing" came from a site still serving `main-CUdvyZSj.js` (v32); candidate: record the bundle hash per release.
