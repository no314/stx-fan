## Read techniques

- **Batch reader on chain** (Zero to Claiming, candidate). A stateless read-only contract takes lists and returns normalized tuples. Known targets get statically bound function pairs (traits are illegal in read-only functions); per-entry context rides inside each list entry (callbacks cannot close over locals); contracts are generated by script per manager and shipped as additive revisions. Client side: start at `CHUNK_START` 40, halve on a cost rejection down to 1, memoize the working chunk per contract and function family, keep progress totals self-correcting. Measured 2026-09-10 on mainnet: a 1-entry batch claim cost 34 reads and 337k runtime, 2 entries 65 reads and 580k, about 30 reads per entry marginal; max500-lineage earned reads about 20 `read_count` each. Per-entry costs pinned as `ENTRY_COST`: settle 27 reads, 180,000 bytes, 8 writes; sBTC payout 14 reads, 4 writes; BTC payout 34 reads, 10 writes; sBTC claim 31 reads, 171,000 bytes, 7 writes; BTC claim 51 reads, 13 writes. A 10 percent transaction share fits eight blocks deep in a tenure.
- **Map without an accessor** (Zero To BNS, BNS Lookup). POST the Clarity-encoded key to `/v2/map_entry/<addr>/<name>/<map>?proof=0` and decode the optional tuple; a failed read returns `{unknown: true}`, never "not listed".
- **Paged REST lists** (Zero To BNS, BNS Lookup, tax export). Loop `offset` until `total`; exercise the loop in fixtures with more rows than one page (60 owned names against a 50 cap).
- **Address history** (tax export). Index the principal through `/extended/v3/principals/{p}/transactions`, union with `stx_lock` events the address did not send, read missing transactions with `/extended/v3/transactions/batch`, fix the closing block before the first read, use the per-transaction balance change as the oracle for the transfer feeds, and read the transaction's own event list only on a mismatch or an NFT change.
- **Discovery of where an address staked** (Zero to Claiming). Read the address's `stx_lock` events (one page of 100 covered whole histories); ask every cataloged pool `get-member` first for pooled bond stakers; set pox-4 locks aside by unlock height.
- **Hand-encoded Clarity values** (sBTC Deposit Recovery, tax export). `principalHex`, `uintHex`, `buffHex` for arguments; a 37-line SIP-005 decoder for results; a standard principal in a result serializes as `05 <version> <hash160>`.
- **Capability by signature** (Zero to Claiming). Read `/v2/contracts/interface`, match function signatures, never names; asserts inside bodies (bond acceptance, fee caps) stay catalog data with a source note and a structure-hash check of any "same body as" claim.
- **Fresh read in the submit path** (Zero to Signing, Zero To BNS). Re-read the burn height, the listing price and the fee contract inside the handler and block with old and new values when they changed.

Switch network and chain id everywhere, offline signers included. Confirm each call's mode and conditions match who moves what. Verify the pinned source on mainnet with a formatting-robust hash. Confirm every supported wallet enforces the conditions on each platform. Add slippage and price sanity. Vendor and pin the served bundles. Remove every testnet shortcut. ### Techniques moved from the skill body

- Test static-principal contracts in simnet by substituting principals and keywords with mocks, and prove the variant differs in exactly those tokens (claiming, gas). Do not compile the project to WASM; the Clarity simnet is a test tool, not a runtime.
- Window boundary tests: blocks 1, 3, 50, 100 and 101 from the window's end, the first block, the first blocked block and a mid-window control. A cycle starting at 150 with length 2100 ends at 2249.
- When preflighting, distinguish wrong network (different boot principal) from not yet activated (same principal, older contract) (signing).
- A node the user controls may switch the read gate off.

- `src/sign-queue.ts`: the sequential sign queue, pure, no UI and no wallet import, ported from Zero to Claiming `runSequential`. - `src/wallet.ts`: connect by chosen provider, `isUserRejectionError`, `sendWalletRequest`, modelled on leather-io/mono `apps/web/app/utils/wallet.ts` at commit 8829674b83488d6011edee415640652eb515a0a8. Every `request` gets the resolved provider with `enableLocalStorage: false` and `forceWalletSelect: false`; connect returns `connected`, `canceled` or `error`. With this the library writes nothing to localStorage, so the harness asserts storage is empty.

- `src/tx-status.ts`, `src/use-tx-statuses.ts`: one read per transaction every 5 seconds, stop when every transaction is final, wait 15 seconds after a refused read, keep the last known status when a read fails, a 404 right after broadcast maps to pending. Two transactions make 24 reads a minute against a budget of 50; more than four open transactions need a gate.

### Read techniques (claiming, usdcx, recovery)

- On a contract that books before it pays, the booked-but-unpaid balance (`get-pending-payout`) is the one read that recovers an interrupted run from nothing (claiming `src/steps.jsx` `pendingRows`, 2026-10-22).
- A contract's own read-only validators can be called through call-read before signing (usdcx: `parse-and-validate-deposit-intent`, `verify-deposit-intent-signature`, `get-remote-recipient`).
- A list record with a missing or default field is treated as incomplete and re-read by id from the primary record before any check that depends on it (recovery, 2026-11-04).
- A field that takes an address or a BNS name treats a contract principal (`<address>.<contract-name>`) as an address first and upper-cases only the c32 part; a contract name is case-sensitive on chain (claiming `src/lib.js` `resolveBnsOwner`, `isBnsName`, 2026-10-29).
