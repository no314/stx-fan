# dApp scaffold and read techniques

Copy-by-path for the wallet and chain layer, plus techniques the SKILL.md body only names. The reference apps live on Werner's machine and as built output in `no314/stx-fan` under `zero_to/`; the paths assume this machine. Updated 2026-10-19 (v3 merge).

## Copy by path

- **Zero to Signing** `src/lib.js`: the wallet and transaction bridge. Vendored bundle imports, WBIP plus legacy provider detection, the known-wallet catalog with capability gating, `callReadOnly`, `resolveBnsName`. `src/vendor/`: pinned known-good `@stacks/connect` and `@stacks/transactions` bundles plus `structure-hash.js` and `contract-sources.js`; copy the files, not the registry versions. `xverse.html`, `src/xverse-page.js`, `src/styles/xverse-page.css`: the blocked-wallet rationale as a second Vite entry. `scripts/verify-hashes.mjs`: hash invariance under reformatting.
- **Zero to Claiming** `src/chain.js`: one gate for every read (`THROTTLE_RPM`, global cooldown, visible stall through `onApiStall`, backoff), transaction lookup paged at `event_limit=100`, chunked read-only list calls that halve on cost rejection and wait out refusals for `READER_PATIENCE`, helper revisions pinned by principal and structure hash with a per-revision cap, verified newest first. `src/core.jsx` `detectShape`: capability detection by function signature from `/v2/contracts/interface`; the tenure-budget cost model. `claim-helper/` beside the app: generated statically bound contracts, simnet tests with `mock-*.clar` substituting principals.
- **sBTC Deposit Recovery** `src/clients.js`: pinned hosts, per-host spacing, retry with backoff, `cb()` cache-buster on every Emily GET, automatic esplora fallback, fixture mode. `src/bns.js`: one contract read without `@stacks/transactions` (Clarity `buff` encoding, `(response (optional principal) uint)` decoding).

- **Zero to Stacks Tax Export** `src/loader.js`: the v3 principal endpoint family with cursors, the lock-event union, the closing block, the balance-change oracle, past-block reads with `?tip=`, `PINNED_TOKENS`, `STSTX_ERAS`. `src/clarity.js` (37 lines, SIP-005 decoder) and `src/bns.js` (three argument encoders). `src/address.js`: c32check with an exact round trip.

## Read techniques

- **Batch reader on chain** (Zero to Claiming, candidate). A stateless read-only contract takes lists and returns normalized tuples. Known targets get statically bound function pairs (traits are illegal in read-only functions); per-entry context rides inside each list entry (callbacks cannot close over locals); contracts are generated by script per manager and shipped as additive revisions. Client side: start at `CHUNK_START` 40, halve on a cost rejection down to 1, memoize the working chunk per contract and function family, keep progress totals self-correcting. Measured 2026-09-10 on mainnet: a 1-entry batch claim cost 34 reads and 337k runtime, 2 entries 65 reads and 580k, about 30 reads per entry marginal; max500-lineage earned reads about 20 `read_count` each. Per-entry costs pinned as `ENTRY_COST`: settle 27 reads, 180,000 bytes, 8 writes; sBTC payout 14 reads, 4 writes; BTC payout 34 reads, 10 writes; sBTC claim 31 reads, 171,000 bytes, 7 writes; BTC claim 51 reads, 13 writes. A 10 percent transaction share fits eight blocks deep in a tenure.
- **Map without an accessor** (Zero To BNS, BNS Lookup). POST the Clarity-encoded key to `/v2/map_entry/<addr>/<name>/<map>?proof=0` and decode the optional tuple; a failed read returns `{unknown: true}`, never "not listed".
- **Paged REST lists** (Zero To BNS, BNS Lookup, tax export). Loop `offset` until `total`; exercise the loop in fixtures with more rows than one page (60 owned names against a 50 cap).
- **Address history** (tax export). Index the principal through `/extended/v3/principals/{p}/transactions`, union with `stx_lock` events the address did not send, read missing transactions with `/extended/v3/transactions/batch`, fix the closing block before the first read, use the per-transaction balance change as the oracle for the transfer feeds, and read the transaction's own event list only on a mismatch or an NFT change.
- **Discovery of where an address staked** (Zero to Claiming). Read the address's `stx_lock` events (one page of 100 covered whole histories); ask every cataloged pool `get-member` first for pooled bond stakers; set pox-4 locks aside by unlock height.
- **Hand-encoded Clarity values** (sBTC Deposit Recovery, tax export). `principalHex`, `uintHex`, `buffHex` for arguments; a 37-line SIP-005 decoder for results; a standard principal in a result serializes as `05 <version> <hash160>`.
- **Capability by signature** (Zero to Claiming). Read `/v2/contracts/interface`, match function signatures, never names; asserts inside bodies (bond acceptance, fee caps) stay catalog data with a source note and a structure-hash check of any "same body as" claim.
- **Fresh read in the submit path** (Zero to Signing, Zero To BNS). Re-read the burn height, the listing price and the fee contract inside the handler and block with old and new values when they changed.
